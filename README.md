# Enemies Waves

При выполнении тестового задания использовал ИИ. ИИ использую для реализации задуманной архитектуры. Сам продумываю архитектуру, уточняю у ИИ что упускаю. Создаю md-файл технического описания проекта (в данном случае это technical-design.md). Когда все описано достаточно подробно и однозначно даю команду ИИ реализовать задуманное. Полностью проверяю что сделала ИИ, вношу правки вручную, итерирую с ИИ. По итогу получается работать быстрее. Весь контекст остается за мной. Это не вайбкодинг, а самостоятельный кодинг с использованием ИИ как инструмента

Техническя реализация: вся игра находится на 1 Unity-сцене Main.unity. Настройки хранятся в `WaveSettings` ScriptableObject: каждая волна содержит сценарий из последовательных `SpawnStep`, задающих prefab врага, количество и интервал спавна. Враги движутся к общей цели, после достижения возвращаются в пул

Зависимости собираются через VContainer. `PoolManager` отвечает только за создание, предзагрузку и возврат любых prefab, а `WaveSpawner` исполняет сценарий волн через UniTask и публикует состояние текущей волны и числа активных врагов. HUD реализован через MVP и отображает эти значения без поиска объектов на сцене

## 1. Как развивать систему для десятков типов врагов и настройки волн геймдизайнером

Если геймдизайнер будет использоват юнити то я сделаю для него удобный инструмент настройки волн с помощью OdinInspecotr. Если геймдизайнер не использует юнити редактор то я вынесу настройку волн в гуглшит и напишу на клиенте парсер данных из этого гуглшита

## 2. Что сделать за неделю вместо нескольких часов

Я бы реализовал логику спавна перемещения и убирания врагов на ECS. Пошел на более простое классическое решение через монобехи чтобы уложиться в 4 часа для тестового

Ресурсы разнёс бы по бандлам и загружал через Addressables. Для них сделал бы отдельный модуль удалённой докачки, который загружает нужные бандлы с сервера. Конфигурацию волн я бы перенес бандл, чтобы hotfix выполнялся заменой бандла без обновления клиента
